# IMU と測位で横すべり角を出す試し（2026-11-16）

SUGO 2026-11-08 決勝の記録で、車体の横すべり角 β（車の向きと進む向きのずれ）を出せるか試した。
きっかけは、デジスパイスのドリフトの機能（iPhone の姿勢センサー＋測位、`docs/research/digspice_analysis_study_20261115.md` 7.1）。

- スクリプト：`slip_angle.py`（`python outputs/slip_angle_20261116/slip_angle.py [キャッシュのフォルダ]`。SDの写し4,243ファイルを読むのに約1分）
- 数：`summary.json`、合わせ直しを抜いた試し：`holdout.csv`
- 図：`beta_laps.png`（30〜32周目の β・後輪の滑り角・横G）、`beta_repeat_and_gradient.png`（25周の同じ所の β、横Gと β）、`checks.png`（時刻のずれ・合わせ直しの外れ）

## やり方

- **進む向き**：シールドのSDに残った u-blox の NAV-PVT（10 Hz 全部）の**速度の向き**（`atan2(velE, velN)`）。位置の差から出すより揺れが小さい。受信機の向きの精度（headAcc）は旋回中の中央値 0.16°
- **車の向き**：BNO055 の角速度を、取り付けの学習で出した「上」の向き（`imu_mount` の up、6.3° 傾き）へ投影して鉛直まわりの回る速さにし、足し合わせる
- **時刻**：NAV-PVT が STM32 に届いた時刻は1つずつ ±20 ms 揺れるので、受信機が測った時刻（itow）を STM32 の時計へ直線で写した時刻を使う。STM32 の時計は受信機より **−0.26 %**（2,623 ppm）遅れて進んでいた
- **倍率**：コーナーの前後2秒の向きの変化を測位に合わせて、角速度に K = 0.966 を掛ける（BNO055 の目盛りの誤差。投影で傾き分は除いてある）
- **合わせ直し**：まっすぐの所（60 km/h 超・|横G| < 0.08・回る速さ < 1.5 °/s が1秒以上）で β = 0 とみなして向きのずれを合わせ直し、あいだは直線でつなぐ（デジスパイスの「ドリフトの前後に1秒まっすぐ」と同じ考え）。決勝で288か所、間隔の中央値 5.5 秒
- **後輪の滑り角**（目安）：α_r = β − b·r / v（b＝重心から後軸、NC の軸距 2.330 m を前後50:50 とみて 1.165 m）。舵角が無くても出せる

### いちばん効くのは「測位が届くまでの遅れ」

NAV-PVT は測った瞬間より遅れて届く。遅れを ΔL 見誤ると、β は「回る速さ × ΔL」だけずれる（30 °/s で 30 ms 見誤ると 0.9°）。
遅れの出し方で値が割れた：

| 出し方 | 遅れ | 偏りの向き |
|---|---|---|
| 角速度 ↔ 測位の向きの変わる速さ | 225 ms | β が育つ分を吸い込んで多めに出るはずだが、横Gの変わる速さの項を足しても 225 ms のまま |
| 車輪速（CAN）↔ 測位の速さ | 180 ms | 車輪速自身の CAN の遅れの分だけ少なめに出る（実際は 180 ＋ 車輪速の遅れ） |
| 生の加速度（前後・横）↔ 測位の速さの変化・向心加速度 | 100〜115 ms | ロール・ピッチで重力が混ざり、少なめに出る |
| 幾何（低い速さで頭が外を向く −b/R）に合う遅れ | 約 185 ms | タイヤの分と見分けにくく、弱い確かめ |

使ったのは 225 ms。遅れを変えたときのふつうのコーナーの β の中央値は、0 ms で +4.5°、100 ms で +2.4°、150 ms で +1.4°、225 ms で −0.1°。
**大きな滑り（5° 超）や周どうしの比べは遅れに関係なく読めるが、ふつうのコーナーの β の絶対値には ±1° ほどの不確かさが残る。**
前の SUGO のレポート（`tools/race_analysis/race_analysis.py` の tire_slip、β の中央値 2.6°）はこの遅れを入れておらず、ふつうのコーナーの β を多めに出していた。
2026-11-16 に、そちらも同じ考え方に直した（GNSS の進む向きを NAV-PVT の速度の向きにし、遅れは進む向きの変わる速さを GyroZ に合わせて 245 ms）。決勝の通常の周で：

| | 直す前 | 直したあと |
|---|---|---|
| ふつうのコーナーの β の中央値 | 2.6° | −0.5° |
| コーナーごとの最大の中央値 | 4.6° | 0.6° |
| 戻りきらない角度の中央値（誤差の目安） | 1.1° | 0.6° |
| 8° 超で「後ろが出た」 | 16 か所 | 4 か所 |

遅れぶん β がかさ上げされて 8° をまたいでいた所が落ち、残ったのは 29周目 C7（23.8°、前は戻りきらない角度 5.1° で「確かでない」として外れていた）・32周目 C4（21.4°）・28周目 C4（8.6°）・33周目 C5（8.2°）。映像で本物と分かっている 11周目 C2 は、SD版では前のコーナーとまとまって今も数に入らない。

遅れをなくすには、受信機のタイムパルス（PPS）を STM32 で時刻取りするのが確実（シールドにつながっているかは未確認。回路の話なので Lintaroh さんに聞く）。

## 舵角センサーがあると何が増えるか

舵角だけでは β は出ない（β は上のとおり IMU と測位で出す）。舵角が増やすのは**前輪の滑り角**：

- 前輪の滑り角 α_f ＝ β ＋ a·r / v − δ（δ＝前輪の切れ角＝ハンドル角 ÷ ステアリングのギア比、a＝重心から前軸）
- 後輪の滑り角 α_r ＝ β − b·r / v（今でも出せる）

前と後ろの滑り角を比べると、**アンダー（前が先に滑る）とオーバー（後ろが先に滑る）を分けて見られる**。
今はオーバーの向き（β・後輪の滑り角が大きい）しか分からず、アンダーは出せない（前のレポートでも同じ）。
ギア比は一定ではない（切れ角で変わる・タイヤの向きのたわみ）ので、低い速さの定常円旋回（滑り角≒0）で実効のギア比を合わせ込んでから使う。
