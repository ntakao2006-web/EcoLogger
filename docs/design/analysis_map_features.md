# 解析アプリの地図の上での解析・比べ（仕様）— 2026-11-15

解析アプリ（SP-10、`ntakao2006-web/ecologger-analysis`）で、プロットした地図の上での解析・比べを強くするための仕様。
作業は`task_spec_rebuild_breakdown.md`の SP-10-12〜10-18。

- 下調べ：デジスパイスは`docs/research/digspice_analysis_study_20261115.md`（今の版 Ver4.8.0 の説明書まで読んだ）、ほかの解析ソフトは 6章
- **ほかのソフトからは機能の考え方だけを借り、画面のデザイン・文言・データは写さない**（SP-10 の決めごと）
- 解析アプリの形式（ecorun）は変えない。足すものは全部、解析アプリの中の計算と、手元に残す設定（`~/.ecologger-analysis/`）

## 1. ねらい

いまの解析アプリは「周を重ねてタイムの差を出す・地図と動画とグラフが一緒に動く」まではできている。足りないのは、

1. **どこで負けたか・何が違ったかを、地図を見ただけで分かる**こと（今はグラフのタイムの差を見て、地図と見比べる）
2. **コーナーごとに数で比べる**こと（ブレーキの踏み始め・ボトムの速さとその位置・脱出の速さ・区間タイム）
3. **ライン取りの違いを数で見る**こと（横にどれだけずれたか、旋回半径はいくつか）
4. **走ったあとすぐ、次に何を直せばいいかが分かる**こと（ピットで数分しか無いときに、グラフを読まずに「伸びしろの大きい所3つ」と「安定していたか」が分かる。Garmin Catalyst が売りにしている見方、6-2）

デジスパイスが強いのは 3（旋回半径と摩擦円）と、地図の上の物差し・アニメーション。1 と 2 はデジスパイスに無く、
プロのインストラクターが勧める見方（コーナーごとの仮想区間、`digspice_analysis_study_20261115.md` 4章）をそのまま機能にする。
4 は Garmin の見方を借りるが、Garmin が隠している「何と比べたか」を表に出し、比べる相手（ベストの周か平均か）を選べるようにする（6-2 のレビューの不満）。

## 2. 下見：手元の記録で使えるか（SUGO 11/8 決勝 31〜33周）

仕様の数を決めるため、NC のロガー（測位10Hz・IMU 50Hz）の記録で測った。測る道具は使い捨て（リポジトリに入れない）。

| 測ったこと | 結果 | 仕様への効き |
|---|---|---|
| **測位から出す横G**（位置を0.5秒＝5点でならしてから2回微分）と IMU の横G（0.3秒でならす） | 相関 0.997、差の rms **0.05 G**。ならさないと 0.08 G、0.9秒ならすと 0.07 G | 測位だけの記録でも横Gと旋回半径は出せる。ならしは0.5秒 |
| 測位から出す前後G（速さの微分）と IMU の前後G | 相関 0.96、差の rms 0.08 G | 前後Gは IMU があればそちらを使う |
| 横Gの向き | IMU の`LatAccel`は**右へ曲がると＋**（測位から出した「左へ曲がると＋」と逆） | 摩擦円・数の表示は右旋回を右（＋）にそろえる |
| 旋回半径の再現性 | 同じコーナーのボトムで、3周とも 30〜32 m（62〜66 km/h）、47〜53 m（80〜86 km/h）、38〜42 m（75〜76 km/h） | 周ごとの数 m の違いを比べられる |
| **ブレーキの踏み始め**（IMU の前後Gが −0.25 G を0.3秒以上下回った所から、−0.05 G まで戻った所） | 31・32周は7か所が**どれも同じ所の±6 m 以内**（99/100、629/631、1044/1046 m…）。32周だけ1か所多い（2552 m、軽く踏んだ所）。33周（遅い周）は2か所が無いか28 m 早い | **区間の切り目は周ごとに自動で切らず、基準の周で一度決めて全部の周に同じ所を使う**（周ごとに切ると、区間の数も場所もそろわない） |
| 2周の走った線の横のずれ（32・33周を31周の線から） | 中央 0.9〜1.1 m、9割が 2.2〜2.8 m 以内、最大 4.9 m・7.6 m。測位の見積もり精度`hacc_m`は 0.16〜0.24 m、衛星 27〜32 | 同じ日の周どうしなら 1 m の違いは本物として読める。**別の日のずれ（デジスパイスが矢印で直させているもの）は測っていない** |

- ブレーキの ON/OFF は NC の CAN（`0x200` byte6 bit0）で取れているが、今の書き出し（SUGO 11/8）のチャンネルには入っていない。ブレーキ圧はセンサーを付ける予定（`docs/design/brake_pressure_sensor_ncec.md`）。**ブレーキの踏み始めは、ブレーキのチャンネルがあればそれ、無ければ前後G**で拾う
- エコランのスマホの記録（測位1Hz）では、0.5秒でならす計算ができない。**測位の間隔が0.25秒より粗い記録では、測位から出す G・旋回半径を作らない**（使えるかは試していない）

## 3. 機能

### 3-1. 地図の線を値で塗る（SP-10-12）

コース図の見出しに「塗る」を足し、周の線の色を選べるようにする。

| 塗る | 中身 |
|---|---|
| 周の色（今のまま。ふだん） | 周ごとにグラフと同じ色 |
| 値 | 車速・前後G・横G・アクセル・回転数・旋回半径・計算チャンネル、から1つ。**塗るのは基準の周の線だけ**で、ほかの周は今の色で細く描く（重ねて塗ると読めないため） |
| タイムの差（増え方） | 2周以上のとき。比べる周（基準の次に選んだ周）の線を、**基準に対して得をした所・損をした所**で塗る。値は「タイムの差の増え方」（2 m 刻みの差を20 m でならし、1 m あたりの秒）。得は青、損は赤、変わらない所は白に近い色。**これで地図を塗れる製品は見つからなかった**（RaceChrono は同じ値を「時間ゲイン」としてグラフにだけ出せ、地図の塗りには選べない。6-4。シム用の Garage 61・VRS・Track Titan・Delta・trophi.ai にも無い。6-5） |
| タイムの差（値） | 同じく比べる周の線を、その所までのタイムの差そのもので塗る（MoTeC のレインボーマップと同じ見方）。手前で失った時間が後ろまで色に残るので、「どこで」を見るなら増え方、「どれだけ」を見るなら値 |

- 色の段は、値なら低い→高いの1方向の段、タイムの差は0を真ん中にした両方向の段。段の範囲はふだん周の中の 2〜98% で決め、手で数を入れて固定もできる（別の周へ移っても同じ色の意味にするため）。図の左下に凡例
- 「減速を点線」（入/切）：前後Gが −0.1 G より小さい所を点線にする（デジスパイスの描き方。塗りと一緒に使える）
- 測位の質が悪い所（`hacc_m` が 1.5 m を超える所、測位が0.3秒より長く抜けた所）は、どの塗り方でもグレーにする
- 「測位の精度」の塗り（Harry's LapTimer の Accuracy の地図）：線の点ごとに`hacc_m`の大きさの円を薄く描く。線のずれが測位のせいか走りのせいかを見分けるため
- 地図にカーソルを当てると、その所の値を数で出す（3-4 の吹き出しと同じ）
- **地図の上の印**（入/切）：選んだ周ごとに、ブレーキの踏み始め（▼）・ブレーキを離した所（前後Gが戻った所、▲）・ボトムの速さの所（●）・直線の最高速の所（○）を、周の色で線の上に置き、速さの数を添える（Harry's LapTimer も速さの極小・極大を地図と動画に自動で出している）。2周のブレーキの位置の違いが地図で見える（Garmin の特許 US12606023B2 の図にある見せ方。区間の表の数と同じ所）
- 裏：重ね合わせの返事（`overlay.compare`）の`track`に、塗る値（線の点ごと）を足す。線の点は今 3000 点まで

### 3-2. 区間（コーナー）ごとの表と理論ベスト（SP-10-13）

**区間**＝コーナーごとの切り目で区切った所。セクター（公式の区切り、3〜4本）とは別の組として持つ。

- **切り目の決め方**：「区間を自動で置く」で、基準の周のブレーキの踏み始め（2章の拾い方）に切り目を置く。前後Gもブレーキのチャンネルも無い記録（スマホなど）では、直線の最高速の所に置く（Circuit Tools の既定と同じ。最高速の所＝ブレーキの始まりなので、区切りの意味は同じ）。区間は「そのコーナーのブレーキの踏み始め」から「次のコーナーのブレーキの踏み始めの手前」まで（`digspice_analysis_study_20261115.md` 4章の仮想区間）。S字・続くコーナーで踏まない所は1区間になる
- 切り目は**セクターの線と同じ「線」**（位置・向き・幅）で持ち、全部の周を線を越えた時刻で切る（周ごとに位置を投影するより正確で、周の切り方と同じ計算が使える）。幅はふだん 30 m（デジスパイスも 15 m×両側）
- 切り目は、地図かグラフの上で足す・消す・動かすができ、隣の区間とつなぐ・2つに分ける・名前（「1コーナー」「ハイポイント」など）を付ける、ができる（AiM の区間の直し方と同じ）。**線の版（`lines.json`、SP-10-5）に区間の線も入れて、コースごとに名前つきで残す**。版を使っていなければ、区間は「その場で置いた分」として次に開くまで覚える
- **表**（周の表の下に「区間」の切り替え）。行が区間、列は選んだ周ごと（最大4周）：

| 列 | 中身 |
|---|---|
| 区間タイム | 切り目から次の切り目まで |
| ベストとの差 | 開いている同じコースの周の中の、その区間のベストとの差。ベストに色 |
| 入口の速さ | 切り目を越えたときの速さ（＝ブレーキを踏み始める速さ） |
| ブレーキの踏み始め | 切り目からの距離（m、＋は奥）。基準の周との差で「何 m 奥で踏んだか」 |
| ボトムの速さ・位置 | 区間の中の最小の速さと、その所が区間の頭から何 m か（手前なら脱出重視、奥なら進入重視） |
| 最小の旋回半径 | ボトムのあたりの旋回半径（m） |
| 出口の速さ | 次の切り目を越えたときの速さ |

- **理論ベスト**：区間ごとのベストを足したもの。セクターの理論ベストも同じ形で、周の表の下に1行出す（セクターは今の周の表にあるが、理論ベストが無い）。区間を細かくしすぎると、入口と出口を別の周から取った走れないタイムになる（Race Technology の注意）。切り目をブレーキの踏み始めに置くのは、1つのコーナーの減速から脱出までが同じ周に入るようにするため（Circuit Tools の考え方と同じ）
- 区間ごとのタイムのばらつき（標準偏差）を表の下に出す（AiM にある。どこが安定していないかを見る）
- **連続ベスト**：周の境目をまたいで、続いた区間を1周ぶんつないだときの最速（AiM の Best rolling）。区間の線を越えた時刻から出せる。理論ベストより「実際に続けて走れた」タイム
- **平均の周**：区間ごとの平均タイム。区間タイムがその区間の中央値より 5% 以上遅い周（前の車に詰まった・ピットへ入った）は、その区間だけ平均から外す（Garmin の特許 US12606023B2 に、詰まった所・ピット・測位の悪い所の重みを下げて平均を出す、とある）
- ブレーキの踏み始めの欄を押すと、2周の動画がその瞬間で止まって並ぶ（どこでブレーキを踏んだかを景色で比べる。Garmin の特許 US12606023B2 の、ブレーキの所の写真を周ごとに並べる見せ方を、今の動画の仕組みでする）
- 色は、基準より遅い区間を赤・速い区間を緑・その区間のベストを紫（Circuit Tools などでよく使われる色の決まり）
- 表の行を押すと、地図をその区間に寄せ、グラフの横の範囲をその区間（前後に少し余らせる）にし、動画をその区間の頭へ動かす
- グラフで横の範囲を選ぶ（拡大する）と、その範囲の頭から終わりまでのタイムの差を周ごとに数で出す（Garage 61 は拡大した範囲で差と合計を計算し直す。6-5）。区間の表に無い所（区間の途中から途中まで）の差を読むため
- 「区間の頭で差を0に」（入/切）：タイムの差のグラフを、区間ごとにその頭で0からにする。1つのコーナーの中で得・損がどう増えるかを見るため（デジスパイスはセクターを置いてそこで差を合わせる）

### 3-3. 旋回半径と摩擦円（SP-10-14）

- 測位から計算するチャンネルを3つ足す：**測位の横G**・**測位の前後G**・**旋回半径**（m）。位置を0.5秒でならしてから微分（2章）。グラフ・計算チャンネル・地図の塗りで、ほかのチャンネルと同じに使える。名前に「測位から計算」と分かる印を付け、センサーの値ではないと断り書きを出す（デジスパイスも断っている）
- 旋回半径は、ほぼまっすぐな所（半径 600 m 超）と遅い所（10 km/h 未満）では出さない（空欄）。直線では横Gが小さく、半径の値が暴れるため（AiM の GPS_Radius も約 600 m＝2000 ft の外は0にしている）
- **摩擦円の枠**（新しい枠「G」。枠の並べ方は SP-10-10 のまま使える。標準の配置ではコース図の枠を左右に割って右に置く）
  - 横軸は横G（右旋回を右）、縦軸は前後G（加速を上）。IMU があればその値、無ければ測位の値（切り替えられる）
  - 選んだ周の全部の点を薄く、カーソルの所の点を濃く大きく、カーソルの所までの直前2秒を線で
  - 目安の線：選んだ周で、向きごと（15°刻み）の合成Gの 99% の値を結んだ線（包絡）を薄く描く。加速側は動力で決まり円にならないので、円より実際に近い（Circuit Tools の「Max Grip」と同じ考え）。タイヤの銘柄で決めない
  - 枠の下に、カーソルの所の横G・前後G・旋回半径・速さを周ごとに数で出す
- **摩擦円の使い方**（%）の計算チャンネル：その所の合成Gを、同じ向きの包絡の値で割ったもの。地図の塗り（3-1 の「値」）とグラフで使える。どこでグリップを使い切れていないかが地図で見える（APEX Pro はアプリで線をこの考えの点数で塗る「rainbow road」。目標のGは走りから学んだ摩擦円で決める。6-5）。包絡はその走行の 99% の値なので、100% を超える所も出る
- 使い方の例（デジスパイスの説明書の130Rの例と同じ見方）：2周のボトムの速さが違っても横Gが同じなら、違いは旋回半径＝ライン取り。表（3-2）の最小の旋回半径と摩擦円で、それを読めるようにする

### 3-4. 地図の上の物差しと線の横のずれ（SP-10-15）

- **物差し**：地図の上で Shift を押しながらドラッグすると、2点の間の距離（m）を出す。離すと消える
- **線の横のずれ**：比べる周が基準の周の線から左右に何 m ずれているかを、重ね合わせのときに計算する（今の投影の計算で、線に沿った距離と一緒に横の距離も出す）。
  - グラフに「線のずれ」（m、進む向きの右が＋）として出せる。横軸が距離のときだけ。Garage 61 も同じグラフ（Line distance、2025-07）を持ち、2周以上入れると自動で出る（6-5）。シムは位置に誤差が無いが、実車の測位は2周の間で中央 1 m 前後ずれる（2章）ので、**1 m より小さいずれは読まない**と、グラフの見出しに断る
  - 地図のカーソルの所で、吹き出しに周ごとの速さ・ずれ・タイムの差を出す
- ブレーキの踏み始めの位置の差は、区間の表（3-2）に出す

### 3-5. 地図の再生を強める（SP-10-16）

- 「追う」（入/切、Circuit Tools の「Centre on Vehicle」と同じ）：再生中・カーソルを動かしている間、基準の周の点が図の真ん中に来るように地図を動かす。拡大は今のまま（ホイールで変えられる）
- 区間の表から「この区間を再生」：その区間の頭から動画とカーソルを動かし、区間の終わりで止める。2周の動画は今の仕組み（同じ距離か同じ時間で並べる、SP-10-6）のまま
- 時間の横軸で「そろえる所」を、周の頭（今）か区間の頭から選べるようにする（区間の頭で2周の時刻をそろえ、そこからの差を見る。デジスパイスの「セクタ位置からの同時スタート」と同じ考え）
- **地図の上の点の置き方**を「同じ場所」（今。距離でそろえる）と「同じ時間」（そろえた所からの経過時間で置く。遅い周の点が後ろに離れていき、差が地図の上で見える）から選ぶ。RaceChrono は比べの横軸の伸び縮み（Position・Linear・Disabled）で同じことを切り替えていて、地図で差を見たいときは伸び縮みを切れと作者が答えている（6-3）

### 3-6. 別の日の線のずれを直す（SP-10-17、まず測ってから）

- デジスパイスは、別の日・別の時間帯の周を重ねると線が平行にずれることがあるとして、矢印キーで走行ごとに線を動かして直させている（説明書 6.4：誤差は短い間の揺れでなく、長い間に少しずつずれる）
- ほかのソフトも平行に動かすだけ（Race Technology は矢印で1つの走行を動かし、回転はしない。RaceRender はドラッグ。RaceChrono は走行ごとに緯度・経度の ± ボタン）。**Harry's LapTimer は「Remove GPS Shift」で、コースの資料の点との差が一番小さくなるように全部の点を平行に動かす**（自動。6-3）
- 解析アプリでは、**別の日の走行どうしで、直線の路面の上で線がどれだけずれているかを先に測り**、1 m を超えることがあれば、走行ごとに平行に動かす直し（地図の上で矢印キー、0.1 m と 1 m 刻み、走行ごとに手元に残す。重ね合わせの距離の計算の前にかける）を足す。手で動かすほかに「基準の走行に合わせる」（線どうしの距離が最小になる平行移動を計算する。Harry's の自動の直しと同じ考えで、相手をコースの点でなく基準の走行の線にする）も付けられる。航空写真の上なら、ずれは路面と線の位置で気づける
- 今はまだ同じコースの別の日の10Hzの記録が手元に少ないので、作るかどうかはそのとき決める

### 3-7. 走行のまとめと伸びしろ（SP-10-18）

Garmin Catalyst の「走ったらまず見る」画面（6-2）の考え方。区間の表（3-2）の数から作る。

- **まとめ**（周の表の上に1段）：ベスト・理論ベスト（区間）・連続ベスト・**ベストと理論ベストの差**、**上位3周・5周の平均と幅**（最も遅い周−最も速い周）。Garmin は上位3周のばらつき（Top 3 Var）を「0.5秒以下は上出来、0.5〜1.0秒はまあまあ、1.0〜2.0秒は安定が最優先、2.0秒以上はわけを探す」と読ませている（Garmin が配る使い方の資料。「Var」の計算の中身は書かれていないので、解析アプリは幅で出し、目安の数はそのまま借りる）
- **伸びしろの大きい区間3つ**：区間ごとに「比べる相手の区間タイム − その区間のベスト」を出し、大きい順に3つを地図の上で目立たせ（区間の線を太く、番号 1〜3）、一覧にする。押すとその区間へ寄る（3-2 と同じ）
  - 比べる相手は**ベストの周**（ふだん）か**平均の周**を選ぶ。Garmin は平均と比べ、速い人から「ベストを縮めたいのに、平均と比べられても役に立たない」と不満が出ている（6-2）。安定させたいときは平均、ベストを縮めたいときはベストの周
  - 3つそれぞれに、その区間のベストの周と比べる相手の違いを「ブレーキ（踏み始めの位置・強さ）」「頂点（ボトムの速さと位置・線の横のずれ）」「速さ（入口と出口の速さ）」の3つに分けて数で出す（Garmin の Braking・Apex・Speed の分け方）。文で助言はしない（どれだけ奥で踏んだかを m で出せば足りる）
  - 区間の中を、地図の印（3-1）で「ブレーキ（踏み始め〜離した所）」「旋回（離した所〜ボトム）」「立ち上がり（ボトム〜次の切り目）」の3つに分け、それぞれで失った・得たタイム（秒）を出し、損を赤・得を緑で塗る（Coach Dave の Delta は1つのコーナーを Braking・Entry・Apex・Exit の4つに分けて緑か赤で示し、赤から直せと勧める。6-5）。立ち上がりには次の直線が入るので、ボトムが低くて直線で失った分は立ち上がりの損に出る（Track Titan が分けて見せる「原因」と「その結果」の結果の側）
  - その区間を「この区間を再生」（3-5）で、ベストの周と比べる相手の点が区間の頭から一緒に走る（Garmin の特許の、2台の点が区間を動く見せ方）
- まとめに使う周は、開いている同じコースの周から選べる（ふだんは今の走行だけ）。Garmin は日をまたいで最適な周を作り、選べないことに不満が出ている（タイヤやコースの状態が違う日の周と比べても届かない）

## 4. やらないこと

| やらない | わけ |
|---|---|
| コース図を自分で作る（内側と外側を1周ずつ走る） | 航空写真（SP-10-11）で路面が見える |
| 公式のセクター・プロの走行データを配る | データを集めて配る仕組みが要る。コースの資料は EcoLogger の`tools/setups/courses/`が正 |
| ドリフトの機能 | グリップ走行とエコランが目的 |
| タイヤの銘柄で限界の円を決める | 記録から 99% の値で描けば足りる |
| 地図の線の Google Earth への書き出し | 航空写真で足りる。要るなら別に起こす |
| コーナーを曲がり具合で自動で見分ける（AiM・MoTeC の直線／コーナーの自動分け） | ブレーキの踏み始めで切れば、コーナーごとの区間になる。見分けの閾値を人が調整する手間が増える |
| 速い所をつないだ「最適な周」の線と、それをつないだ動画（Garmin の True Optimal Lap） | 作り方が Garmin の米国特許（US11710421B2・US11710422B2、2026-11 時点で有効）の請求の中身そのもの（1.5 m 刻みで速いほうの周を選び、線が同じ所を通る点でつなぎ替え、動画もつなぐ）。区間のベストを足す理論ベスト（AiM などが昔からしている）と連続ベストで、数は足りる。特許の出願は米国だけに見える（Google Patents の出願の一覧）が、解析アプリは世界中から入手できるので、まねない |
| 走りながらの声の助言、ほかの人との順位表、ドラッグレースの計測（Garmin） | 解析アプリは走ったあとに見る道具。ロガー側の話 |
| 印刷向けの1枚のレポート（Circuit Tools の Track Report） | 今回は画面の上の解析に絞る。要るなら区間の表ができたあとで起こす |
| 改善の候補を自動で挙げる（Garmin Catalyst の「ブレーキ・頂点・速さ」の3つ） | 区間の表で人が読める。自動で言うには判定の決まりが要る |
| 文の助言・損失のシミュレーション（Track Titan の数千通りのシミュレーション、Delta・trophi.ai の AI の助言） | 正確な車のモデルと誤差の無い位置・ペダル・舵角（シム）が前提。実車の測位は線が 1 m 前後ずれ、ブレーキ・舵角のチャンネルも無い。区間の中を3つに分けた秒（3-7）で足りる |
| 地図・グラフへのメモ書き（Garage 61 の解析メモ） | 今は一人で見る道具。人と一緒に見るようになったら起こす |

### 6-2. Garmin Catalyst（初代 2020年・Catalyst 2 2026年2月）

### 6-4. RaceChrono を手元のスマホで動かした（2026-11-15）

RaceChrono Pro 10.3.0（Android、Pixel 9a）に、SUGO 11/8 決勝 31〜33周の VBO（`drive_logs/ct_test_20261108/SUGO_20261108_sd.vbo`、10 Hz）を「インポート」→「VBOX/VBOX Sport」で読ませ、コースはアプリの資料の「SUGO Sportsland」（公式。区切り3本＋コントロールライン）を選んで画面を見た。上の表の【実機】はここで見たもの。

**周と区間**

- 周のタイムは 1:50.11・1:51.99・1:54.94。31周は解析アプリ（ロガーの線）だと 1:50.094 で、コントロールラインの位置が違うのに 0.02 秒で合う
- 走行の画面に「ベストラップ」と「仮想ベスト」（区間ベストの和）が並ぶ。この3周は1周目が全区間ベストなので同じ数
- 周の表は「概要・セクター・スプリット・計算値チャネル・GPSチャネル」の切り替え。**計算値チャネルは、チャンネルごとに周の最大・最小・平均を並べ、列の中で良い方を緑・悪い方を赤で塗る**（速さ、横・前後・合成のG、リーニング角、更新率）。仮想ベストの行も同じ列で出る
- 測位から計算した横Gは ±1.2 G 前後（IMU と同じくらい。2章の下見の結果と合う）。10 Hz の記録を更新率 20 Hz と出す（中で補っている）

**地図**

- 地図の設定は3つだけ：地図の種類（衛星写真・道路地図・シンプル）、**高/低マーカーチャネル**、**運転ラインカラーチャネル**（既定は縦加速度）
- 線の色の段の凡例は無い。速度デルタで塗ると、この3周（差が小さい）では周のほとんどが同じ色で、どこで差がついたかは地図から読めなかった。**解析アプリの塗り（3-1）は凡例と段の範囲（2〜98%・手で固定）を必ず付ける**
- 地図は再生のカーソルを追って動き、指で動かす・広げるのはできなかった（追う切り替えがあるかは見ていない）。3-5 の「車を追う」は入/切にする
- 区切りの線は青い矢印つきの線で、名前（1st split など）の札が付く

**グラフ**

- グラフは1枚で、選んだチャンネルを全部重ね、チャンネルごとに目盛りを別に取る（目盛りの数字は右に並ぶ）。比べる周は同じ色の暗い線で重なる。チャンネルを3つ4つ入れると線が混んで読みにくい
- 下の帯に、カーソルの所の値を主・比べる周の順に並べる（距離 0.779 km／0.776 km、速さ 72.1／74.5 km/h、時間デルタ −0.20 s など）。Position で合わせているので、同じ地点でも距離の数が少し違う
- グラフの設定：**X軸は距離・時間**、**比較グラフ**（入/切。既定は切）、**X軸のスケーリングの比較は位置・線形・無効化**（既定は位置。6-3 の作者の説明どおり）
- 時間の差に関わるチャンネルは「時間デルタ」と「**時間ゲイン**」（その所で得をしているか損をしているかの割合）。どちらも主と比べる周の1本だけ（周ごとの色は無い）。**時間ゲインは 3-1 の「タイムの差（増え方）」と同じ考えだが、グラフにしか出せない**
- 計算チャンネルは デバイス更新率・リーニング角・横加速度・組み合わせた加速度・縦加速度・速度・速度デルタ。**旋回半径・摩擦円の上での包絡は無い**
- 「G円」の枠は、その周の横G・縦Gの点を全部打つだけ（包絡や方向ごとの最大は無い）。3-3 の包絡はこれより一歩進む

**画面の並び**

- 枠は 動画・動画2・地図・G円・グラフ の5つを右上のボタンで出し入れし、縦に積む（大きさは変えられない）。解析アプリは並びと大きさを自由に変えられる（SP-10-9・10-10）

**仕様への効き**

- 3-1：地図の塗りに「タイムの差（増え方）」を入れるのは、RaceChrono に無い（グラフの時間ゲインはある）。凡例・段の範囲を必ず付ける
- 3-1 の地図の上の印は、RaceChrono の高/低マーカーのように**チャンネルを選べる**ようにする（ふだんは速さ）
- 3-2：周の表に「計算値チャネル」のような周ごとの最大・最小・平均の切り替えと、列ごとの良し悪しの色を足す（区間の表と同じ色の付け方）
- グラフは今のまま（チャンネルごとの段を分けて積む）。重ねる方式は混んで読めない
