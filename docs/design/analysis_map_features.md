# 解析アプリの地図の上での解析・比べ（仕様）— 2026-11-15

解析アプリ（SP-10、`ntakao2006-web/ecologger-analysis`）で、プロットした地図の上での解析・比べを強くするための仕様。
作業は`task_spec_rebuild_breakdown.md`の SP-10-12〜10-17。

- 下調べ：デジスパイスは`docs/research/digspice_analysis_study_20261115.md`（今の版 Ver4.8.0 の説明書まで読んだ）、ほかの解析ソフトは 6章
- **ほかのソフトからは機能の考え方だけを借り、画面のデザイン・文言・データは写さない**（SP-10 の決めごと）
- 解析アプリの形式（ecorun）は変えない。足すものは全部、解析アプリの中の計算と、手元に残す設定（`~/.ecologger-analysis/`）

## 1. ねらい

いまの解析アプリは「周を重ねてタイムの差を出す・地図と動画とグラフが一緒に動く」まではできている。足りないのは、

1. **どこで負けたか・何が違ったかを、地図を見ただけで分かる**こと（今はグラフのタイムの差を見て、地図と見比べる）
2. **コーナーごとに数で比べる**こと（ブレーキの踏み始め・ボトムの速さとその位置・脱出の速さ・区間タイム）
3. **ライン取りの違いを数で見る**こと（横にどれだけずれたか、旋回半径はいくつか）

デジスパイスが強いのは 3（旋回半径と摩擦円）と、地図の上の物差し・アニメーション。1 と 2 はデジスパイスに無く、
プロのインストラクターが勧める見方（コーナーごとの仮想区間、`digspice_analysis_study_20261115.md` 4章）をそのまま機能にする。

## 2. 下見：手元の記録で使えるか（SUGO 11/8 決勝 31〜33周）

仕様の数を決めるため、NC のロガー（測位10Hz・IMU 50Hz）の記録で測った。測る道具は使い捨て（リポジトリに入れない）。

| 測ったこと | 結果 | 仕様への効き |
|---|---|---|
| **測位から出す横G**（位置を0.5秒＝5点でならしてから2回微分）と IMU の横G（0.3秒でならす） | 相関 0.997、差の rms **0.05 G**。ならさないと 0.08 G、0.9秒ならすと 0.07 G | 測位だけの記録でも横Gと旋回半径は出せる。ならしは0.5秒 |
| 測位から出す前後G（速さの微分）と IMU の前後G | 相関 0.96、差の rms 0.08 G | 前後Gは IMU があればそちらを使う |
| 横Gの向き | IMU の`LatAccel`は**右へ曲がると＋**（測位から出した「左へ曲がると＋」と逆） | 摩擦円・数の表示は右旋回を右（＋）にそろえる |
| 旋回半径の再現性 | 同じコーナーのボトムで、3周とも 30〜32 m（62〜66 km/h）、47〜53 m（80〜86 km/h）、38〜42 m（75〜76 km/h） | 周ごとの数 m の違いを比べられる |
| **ブレーキの踏み始め**（IMU の前後Gが −0.25 G を0.3秒以上下回った所から、−0.05 G まで戻った所） | 31・32周は7か所が**どれも同じ所の±6 m 以内**（99/100、629/631、1044/1046 m…）。32周だけ1か所多い（2552 m、軽く踏んだ所）。33周（遅い周）は2か所が無いか28 m 早い | **区間の切り目は周ごとに自動で切らず、基準の周で一度決めて全部の周に同じ所を使う**（周ごとに切ると、区間の数も場所もそろわない） |
| 2周の走った線の横のずれ（32・33周を31周の線から） | 中央 0.9〜1.1 m、9割が 2.2〜2.8 m 以内、最大 4.9 m・7.6 m。測位の見積もり精度`hacc_m`は 0.16〜0.24 m、衛星 27〜32 | 同じ日の周どうしなら 1 m の違いは本物として読める。**別の日のずれ（デジスパイスが矢印で直させているもの）は測っていない** |

- ブレーキの ON/OFF は NC の CAN（`0x200` byte6 bit0）で取れているが、今の書き出し（SUGO 11/8）のチャンネルには入っていない。ブレーキ圧はセンサーを付ける予定（`docs/design/brake_pressure_sensor_ncec.md`）。**ブレーキの踏み始めは、ブレーキのチャンネルがあればそれ、無ければ前後G**で拾う
- エコランのスマホの記録（測位1Hz）では、0.5秒でならす計算ができない。**測位の間隔が0.25秒より粗い記録では、測位から出す G・旋回半径を作らない**（使えるかは試していない）

## 3. 機能

### 3-1. 地図の線を値で塗る（SP-10-12）

コース図の見出しに「塗る」を足し、周の線の色を選べるようにする。

| 塗る | 中身 |
|---|---|
| 周の色（今のまま。ふだん） | 周ごとにグラフと同じ色 |
| 値 | 車速・前後G・横G・アクセル・回転数・旋回半径・計算チャンネル、から1つ。**塗るのは基準の周の線だけ**で、ほかの周は今の色で細く描く（重ねて塗ると読めないため） |
| タイムの差（増え方） | 2周以上のとき。比べる周（基準の次に選んだ周）の線を、**基準に対して得をした所・損をした所**で塗る。値は「タイムの差の増え方」（2 m 刻みの差を20 m でならし、1 m あたりの秒）。得は青、損は赤、変わらない所は白に近い色。**これをはっきり仕様にしている製品は見つからなかった**（6章） |
| タイムの差（値） | 同じく比べる周の線を、その所までのタイムの差そのもので塗る（MoTeC のレインボーマップと同じ見方）。手前で失った時間が後ろまで色に残るので、「どこで」を見るなら増え方、「どれだけ」を見るなら値 |

- 色の段は、値なら低い→高いの1方向の段、タイムの差は0を真ん中にした両方向の段。段の範囲はふだん周の中の 2〜98% で決め、手で数を入れて固定もできる（別の周へ移っても同じ色の意味にするため）。図の左下に凡例
- 「減速を点線」（入/切）：前後Gが −0.1 G より小さい所を点線にする（デジスパイスの描き方。塗りと一緒に使える）
- 測位の質が悪い所（`hacc_m` が 1.5 m を超える所、測位が0.3秒より長く抜けた所）は、どの塗り方でもグレーにする
- 地図にカーソルを当てると、その所の値を数で出す（3-4 の吹き出しと同じ）
- 裏：重ね合わせの返事（`overlay.compare`）の`track`に、塗る値（線の点ごと）を足す。線の点は今 3000 点まで

### 3-2. 区間（コーナー）ごとの表と理論ベスト（SP-10-13）

**区間**＝コーナーごとの切り目で区切った所。セクター（公式の区切り、3〜4本）とは別の組として持つ。

- **切り目の決め方**：「区間を自動で置く」で、基準の周のブレーキの踏み始め（2章の拾い方）に切り目を置く。前後Gもブレーキのチャンネルも無い記録（スマホなど）では、直線の最高速の所に置く（Circuit Tools の既定と同じ。最高速の所＝ブレーキの始まりなので、区切りの意味は同じ）。区間は「そのコーナーのブレーキの踏み始め」から「次のコーナーのブレーキの踏み始めの手前」まで（`digspice_analysis_study_20261115.md` 4章の仮想区間）。S字・続くコーナーで踏まない所は1区間になる
- 切り目は**セクターの線と同じ「線」**（位置・向き・幅）で持ち、全部の周を線を越えた時刻で切る（周ごとに位置を投影するより正確で、周の切り方と同じ計算が使える）。幅はふだん 30 m（デジスパイスも 15 m×両側）
- 切り目は、地図かグラフの上で足す・消す・動かすができ、隣の区間とつなぐ・2つに分ける・名前（「1コーナー」「ハイポイント」など）を付ける、ができる（AiM の区間の直し方と同じ）。**線の版（`lines.json`、SP-10-5）に区間の線も入れて、コースごとに名前つきで残す**。版を使っていなければ、区間は「その場で置いた分」として次に開くまで覚える
- **表**（周の表の下に「区間」の切り替え）。行が区間、列は選んだ周ごと（最大4周）：

| 列 | 中身 |
|---|---|
| 区間タイム | 切り目から次の切り目まで |
| ベストとの差 | 開いている同じコースの周の中の、その区間のベストとの差。ベストに色 |
| 入口の速さ | 切り目を越えたときの速さ（＝ブレーキを踏み始める速さ） |
| ブレーキの踏み始め | 切り目からの距離（m、＋は奥）。基準の周との差で「何 m 奥で踏んだか」 |
| ボトムの速さ・位置 | 区間の中の最小の速さと、その所が区間の頭から何 m か（手前なら脱出重視、奥なら進入重視） |
| 最小の旋回半径 | ボトムのあたりの旋回半径（m） |
| 出口の速さ | 次の切り目を越えたときの速さ |

- **理論ベスト**：区間ごとのベストを足したもの。セクターの理論ベストも同じ形で、周の表の下に1行出す（セクターは今の周の表にあるが、理論ベストが無い）。区間を細かくしすぎると、入口と出口を別の周から取った走れないタイムになる（Race Technology の注意）。切り目をブレーキの踏み始めに置くのは、1つのコーナーの減速から脱出までが同じ周に入るようにするため（Circuit Tools の考え方と同じ）
- 区間ごとのタイムのばらつき（標準偏差）を表の下に出す（AiM にある。どこが安定していないかを見る）
- 色は、基準より遅い区間を赤・速い区間を緑・その区間のベストを紫（Circuit Tools などでよく使われる色の決まり）
- 表の行を押すと、地図をその区間に寄せ、グラフの横の範囲をその区間（前後に少し余らせる）にし、動画をその区間の頭へ動かす
- 「区間の頭で差を0に」（入/切）：タイムの差のグラフを、区間ごとにその頭で0からにする。1つのコーナーの中で得・損がどう増えるかを見るため（デジスパイスはセクターを置いてそこで差を合わせる）

### 3-3. 旋回半径と摩擦円（SP-10-14）

- 測位から計算するチャンネルを3つ足す：**測位の横G**・**測位の前後G**・**旋回半径**（m）。位置を0.5秒でならしてから微分（2章）。グラフ・計算チャンネル・地図の塗りで、ほかのチャンネルと同じに使える。名前に「測位から計算」と分かる印を付け、センサーの値ではないと断り書きを出す（デジスパイスも断っている）
- 旋回半径は、ほぼまっすぐな所（半径 600 m 超）と遅い所（10 km/h 未満）では出さない（空欄）。直線では横Gが小さく、半径の値が暴れるため（AiM の GPS_Radius も約 600 m＝2000 ft の外は0にしている）
- **摩擦円の枠**（新しい枠「G」。枠の並べ方は SP-10-10 のまま使える。標準の配置ではコース図の枠を左右に割って右に置く）
  - 横軸は横G（右旋回を右）、縦軸は前後G（加速を上）。IMU があればその値、無ければ測位の値（切り替えられる）
  - 選んだ周の全部の点を薄く、カーソルの所の点を濃く大きく、カーソルの所までの直前2秒を線で
  - 目安の線：選んだ周で、向きごと（15°刻み）の合成Gの 99% の値を結んだ線（包絡）を薄く描く。加速側は動力で決まり円にならないので、円より実際に近い（Circuit Tools の「Max Grip」と同じ考え）。タイヤの銘柄で決めない
  - 枠の下に、カーソルの所の横G・前後G・旋回半径・速さを周ごとに数で出す
- 使い方の例（デジスパイスの説明書の130Rの例と同じ見方）：2周のボトムの速さが違っても横Gが同じなら、違いは旋回半径＝ライン取り。表（3-2）の最小の旋回半径と摩擦円で、それを読めるようにする

### 3-4. 地図の上の物差しと線の横のずれ（SP-10-15）

- **物差し**：地図の上で Shift を押しながらドラッグすると、2点の間の距離（m）を出す。離すと消える
- **線の横のずれ**：比べる周が基準の周の線から左右に何 m ずれているかを、重ね合わせのときに計算する（今の投影の計算で、線に沿った距離と一緒に横の距離も出す）。
  - グラフに「線のずれ」（m、進む向きの右が＋）として出せる。横軸が距離のときだけ
  - 地図のカーソルの所で、吹き出しに周ごとの速さ・ずれ・タイムの差を出す
- ブレーキの踏み始めの位置の差は、区間の表（3-2）に出す

### 3-5. 地図の再生を強める（SP-10-16）

- 「追う」（入/切、Circuit Tools の「Centre on Vehicle」と同じ）：再生中・カーソルを動かしている間、基準の周の点が図の真ん中に来るように地図を動かす。拡大は今のまま（ホイールで変えられる）
- 区間の表から「この区間を再生」：その区間の頭から動画とカーソルを動かし、区間の終わりで止める。2周の動画は今の仕組み（同じ距離か同じ時間で並べる、SP-10-6）のまま
- 時間の横軸で「そろえる所」を、周の頭（今）か区間の頭から選べるようにする（区間の頭で2周の時刻をそろえ、そこからの差を見る。デジスパイスの「セクタ位置からの同時スタート」と同じ考え）

### 3-6. 別の日の線のずれを直す（SP-10-17、まず測ってから）

- デジスパイスは、別の日・別の時間帯の周を重ねると線が平行にずれることがあるとして、矢印キーで走行ごとに線を動かして直させている（説明書 6.4：誤差は短い間の揺れでなく、長い間に少しずつずれる）
- ほかのソフトも自動では合わせず、平行に動かすだけ（Race Technology は矢印で1つの走行を動かし、回転はしない。RaceRender はドラッグ）
- 解析アプリでは、**別の日の走行どうしで、直線の路面の上で線がどれだけずれているかを先に測り**、1 m を超えることがあれば、走行ごとに平行に動かす直し（地図の上で矢印キー、0.1 m と 1 m 刻み、走行ごとに手元に残す。重ね合わせの距離の計算の前にかける）を足す。手で動かすほかに「基準の走行に合わせる」（線どうしの距離が最小になる平行移動を計算する）も付けられる。航空写真の上なら、ずれは路面と線の位置で気づける
- 今はまだ同じコースの別の日の10Hzの記録が手元に少ないので、作るかどうかはそのとき決める

## 4. やらないこと

| やらない | わけ |
|---|---|
| コース図を自分で作る（内側と外側を1周ずつ走る） | 航空写真（SP-10-11）で路面が見える |
| 公式のセクター・プロの走行データを配る | データを集めて配る仕組みが要る。コースの資料は EcoLogger の`tools/setups/courses/`が正 |
| ドリフトの機能 | グリップ走行とエコランが目的 |
| タイヤの銘柄で限界の円を決める | 記録から 99% の値で描けば足りる |
| 地図の線の Google Earth への書き出し | 航空写真で足りる。要るなら別に起こす |
| コーナーを曲がり具合で自動で見分ける（AiM・MoTeC の直線／コーナーの自動分け） | ブレーキの踏み始めで切れば、コーナーごとの区間になる。見分けの閾値を人が調整する手間が増える |
| 印刷向けの1枚のレポート（Circuit Tools の Track Report） | 今回は画面の上の解析に絞る。要るなら区間の表ができたあとで起こす |
| 改善の候補を自動で挙げる（Garmin Catalyst の「ブレーキ・頂点・速さ」の3つ） | 区間の表で人が読める。自動で言うには判定の決まりが要る |

## 6. ほかの解析ソフトの地図まわり（2026-11-15 調べ）

ウェブの公式の説明書・ヘルプ（【文書】）と、フォーラム・記事（【二次】）から。Garmin Catalyst の説明書（PDF）は中身が読めず、
Harry's LapTimer・TrackAddict・RaceChrono は公式の説明が見つからなかった。MoTeC のフォーラムは移転していて一部しか読めていない。

| 項目 | 見つかったこと | 仕様への効き |
|---|---|---|
| 線をチャンネルで塗る | AiM（Race Studio 3）：周ごと・チャンネルの値・区間ごと・単色・Time Compare から選ぶ。目盛りは自動か手で範囲【文書】。MoTeC i2：Track Report で色の段（凡例つき）。2周は図を左右に並べる【文書】。Circuit Tools 3：Heat Map（周とチャンネルを選ぶ）、合成Gで塗る「Combo G Map」【文書】。Race Technology：ブレーキ中は青・加速中は赤【文書】 | 3-1 の形（値を選ぶ、範囲は自動か手で、凡例）でよい |
| タイムの差で塗る | MoTeC はタイムの差の**値**で塗る（同じ距離に着くまでの時間の差）【二次】。**増え方（距離あたり）で塗ると書いた製品は見つからなかった** | 3-1 に値と増え方の両方を置く |
| 区間の切り方 | Circuit Tools：既定は**最高速の所で切る**（直線の終わり＝ブレーキの始まり。各コーナーの減速と加速が同じ周から来るので理論ベストが現実的になる）。ほかに加減速の最大・等距離・手で置く【文書】。AiM：直線／左／右の自動分け・等分・公式。区間はつなぐ・分ける・名前・種別で直し、コースごとに残る【文書】。MoTeC：直線とコーナーを係数で自動分け【二次】 | 3-2：ブレーキの踏み始め、無ければ最高速の所。直し方は AiM と同じ |
| 理論ベスト | AiM：区間のベストの和と、続いた区間の最速の1周（Best rolling）、区間ごとの標準偏差【文書】。Circuit Tools：Ideal Lap（走行の中）と Multi Lap（走行をまたぐ）、動画をつなげる【文書】。Race Technology：細かく切りすぎると走れないタイムになると注意【文書】。Garmin：「True Optimal Lap」は走った線をつないで作る（つなぎ方は非公開）【二次】 | 3-2 の理論ベストとばらつき |
| 旋回半径・摩擦円 | AiM：GPS_Radius＝速さ²÷横G、約 600 m の外は0【文書・二次】。G-G 図は GPS の横G×前後G【文書】。Circuit Tools：コーナーごとの合成Gの跡、目標の円、セッションの最大の包絡（Max Grip）【文書】 | 3-3：半径は 600 m で切る、目安は包絡の線 |
| 地図の上で測る | 2点の距離・2周の線の横のずれを地図で出す機能は、どの製品の説明にも見つからなかった。Racelogic は「同じ距離でも線の違いで186 m 離れていた例」を挙げて、位置で合わせる理由にしている【文書】 | 3-4 は解析アプリの強みになる |
| 地図の再生 | AiM：複数の周の点が時間に沿って動く【文書】。Circuit Tools：Centre on Vehicle で車を追う、最大6周を動画と一緒に【文書】 | 3-5 |
| 日のちがうずれ | Circuit Tools：横軸を「位置」にして同じ所で比べる（良い測位が前提）【文書】。Race Technology：矢印で1つの走行を平行に動かす、回転なし【文書】。RaceRender：ドラッグ【文書】。自動で合わせる製品は見つからなかった | 3-6 |
