# デジスパイスの解析ソフトの調べ（地図の上での解析・比べ）— 2026-11-15

解析アプリ（SP-10、`ntakao2006-web/ecologger-analysis`）で、プロットした地図の上での解析・比べを強くするための下調べ。
デジスパイス（DigSpice）は国内でよく使われるGPSロガーで、PCの解析ソフトが付いてくる。
**機能の考え方だけを参考にし、画面のデザイン・文言・データ（コース図など）は写さない**（SP-10 の決めごと）。

## 1. 機械とソフトの前提

- 今の機種はデジスパイスⅣ：測位は最高20Hz（10Hz・5Hzも選べる）、精度 CEP 1.5m、GPS・みちびき・GLONASS・BeiDou・Galileo。旧機種Ⅲは最高10Hz、初代は10Hz・5Hz・2Hz
- 解析ソフトはWindowsだけ。**デジスパイスで取ったデータしか開けない**（説明書のFAQ）
- **センサーは無く、GもGPSの速度と位置だけから計算する**（Ver1.5.1 の案内に、センサーの値ではないと明記）
- 走行データを読むと、コース図とコントロールラインを自動で選び、周に切る（国内114・海外50コース、2021年12月時点）。スタートとゴールが違う競技（ラリー・ヒルクライム）は自分で線を置く。止まった所を○で出して、スタートの位置を探しやすくする

## 2. 地図の上でできること

| 機能 | 中身 | 出典 |

| アニメーション | 選んだ周（最大4台）が地図の上を同時に走る。拡大して追える。再生・止める・コマ送り・速さ（1/2〜8倍） | 説明書 7.1.2・7.2.3、ブログ |
| **地図の上の物差し** | 赤の車（基準）の先頭から**マウスの位置までの距離**を出す。ライン取りやブレーキの位置を測るため | 説明書 7.2.3 |
| 時間と数値 | スタートからの赤の車の所要時間、周のタイム・平均の速さ・最高速、カーソルの所の距離と速さ | 説明書 7.2.3 |

- 地図の線を速さやGで色分けする機能は、見つけた資料には無い
- 地図の上でのタイムの差（どこで得・損をしたか）の表示も、見つけた資料には無い

## 3. グラフと比べ

- **速度のグラフ**：横軸は距離と時間を切り替えられる。グレーの線で高さ（標高）。ダブルクリックでカーソルを置き、その所の速さを棒で出す。カーソルを中心に拡大（説明書 7.2.1）
- **G と旋回半径**（Ver1.5.1 で追加）
  - 摩擦円（横G×前後Gの散布図）：重ねた周の**全部の点を薄く**、**カーソルの所の点を濃く大きく**出す。横軸が距離なら基準の車の位置で、時間ならそれぞれの車のその時刻で
  - 旋回半径：カーソルの所の旋回半径（m）を出す。マウスの所の値を「横G・前後G・半径」の3つの数で出す
  - 計算は、横G＝速さ²÷旋回半径÷g、前後G＝速さの差÷時間の差÷g（g＝9.80665）
  - 使い方の例（鈴鹿の130R、2台）：ボトムの速さが23 km/h違うが、横Gは2台とも約1.1Gで限界。**違いは旋回半径（150 m と 205 m）で、遅い車はラインが小さいから減速せざるをえなかった**、と読む。「Gは同じ、半径が違う → ライン取りを直す」という見方
  - 摩擦円の見方：点が円周に集まるほどタイヤを使い切っている。目安はスポーツラジアル約1.2G、Sタイヤ約1.5G
- **周の一覧**：周・時刻・タイム・最高速・セクター。上位3つを色分け（ベスト・2番・3番）
- **セクターの理論ベスト**：選んだ周のセクターのベストを足した時間（説明書 7.2.2 の「セクタ詳細」、みんカラの「仮想ベスト」）
- **プロの走行データとの比べ**：公式サイトでプロ・有名選手の走行データを配り、自分の周と重ねられる
- **動画**：車載動画を読み込んで周のデータと同期させる（2013年のブログ）。同期すると、データを送れば映像も送られ、別の周と比べても同期が保たれる。同期は手で合わせる形と読める
- 書き出し：CSV（周の一覧・走行の詳細）、走行を再現した動画（AVI）

## 4. 使う人の見方（記事・ブログから）

モーターファンの記事（講師はプロのインストラクター）が勧める見方は、そのまま解析アプリの機能の要求になる。

1. 縦軸を速さ、**横軸を距離**にしたグラフで2周を重ねる
2. 公式のセクターでなく、**コーナーごとの仮想区間**で切る。区間は「そのコーナーのブレーキを踏み始めた所」から「次のコーナーのブレーキを踏む直前」まで。S字・複合コーナーは1区間。ブレーキの位置は車や天気で変わるので、区間は適宜直す
3. 区間ごとの最速を足した**仮想ベスト**を出し、区間ごとにベストの周とほかの周を比べる
4. 比べる所：ライン取り（ボトムの速さを保つ大回りか、距離の短い小回りか）、ブレーキの踏み始めと強さと離す所、シフトの回転数と速さ、**ボトムの速さの位置**（手前なら脱出重視、奥なら進入重視）、ブレーキから旋回へのGの移り方（円を描くか、直線的か）

使う人のブログから：

- 2周を重ね、速度グラフの傾きから「ブレーキが25 m早かった」と読む。ブレーキ開始から60 m先の速さを比べる（距離の横軸が前提）
- 摩擦円は、山型より楕円に近いほうがよい
- **別の枠（日・時間帯）の周を比べるには、GPSのずれのため、走行ラインを矢印で動かしてコースに合わせてから保存する手間がある**（みんカラ）
- 「取扱説明書が無いので分かりにくい」という声（みんカラのコメント）

## 5. 解析アプリとの比べ

| | デジスパイス | 解析アプリ（11/15の時点） |
|---|---|---|
| 地図の背景 | 自分で作るコース図（路面の縁の線） | 国土地理院の航空写真（SP-10-11） |
| 線の描き分け | 減速は点線、受信不安定はグレー | 周ごとの色だけ |
| 地図の上の物差し | 基準の車からマウスまでの距離 | 無い |
| アニメーション | 最大4台が地図を走る | 動画の再生でカーソルの点が動く（追って拡大は無い） |
| 摩擦円・旋回半径 | GPSから計算して出す | 無い（加速度のチャンネルはグラフに出せる） |
| 周を重ねる | 4本まで | 8本まで。**距離は位置で合わせ、タイムの差を出す** |
| 地図の上のタイムの差 | 無い | 無い（グラフのタイムの差だけ） |
| セクター・理論ベスト | 任意の区切り、理論ベストあり | 線の版で区切れる。**理論ベストは無い** |
| コーナーごとの表 | 無い | 無い |
| 動画 | 読み込んで手で同期 | 書き出しの対応表で自動で合う。2本並べる |
| 車のデータ | 無い（GPSだけ） | CANの物理量（アクセル・回転数・水温など）と、式で作る計算チャンネル |

## 6. 解析アプリに入れたらよさそうなもの（案）

地図の上での解析・比べに絞って、効きそうな順。デジスパイスに無いものも、上の見方（4章）から足した。

1. **地図の線を値で塗る**：周の線を、車速・前後G・横G・アクセル・ブレーキ（減速を点線にするのも含む）で塗り分ける。2周のときは**基準の周に対して得をした所・損をした所**（タイムの差の増え方）で基準の線を塗る。どこで負けたかが地図で一目で分かる。デジスパイスに無い
2. **コーナーごとの表と理論ベスト**：ブレーキの踏み始めで自動で区間を切り（4章の仮想区間）、区間ごとに「ブレーキ開始の位置・ボトムの速さとその位置・脱出の速さ・区間タイム・ベストとの差」を並べる。区間のベストを足した理論ベストも。表の行を押すと地図・グラフ・動画がその区間へ動く。区間の切り目は地図で直せる（線の版と同じ形で残す）
3. **旋回半径と摩擦円**：旋回半径をチャンネルとして出し（測位から計算）、地図のカーソルの所に半径と横G・前後Gを出す。摩擦円の小窓（全部の点を薄く、カーソルの所を濃く）。NCのロガーはIMU（BNO055）の加速度もあるので、GPSから計算した値と並べられる。130Rの例のように「Gは同じで半径が違う」を見られる
4. **地図の上の物差し**：2点間の距離、カーソルの所での2周の横のずれ（ライン取りの差を m で）、ブレーキ開始の位置の差（m）
5. **地図のアニメーションを強める**：再生中に選んだ周の点が全部動く（今もできる）のに加えて、車を追って拡大する、周の頭や区間の頭から再生する
6. **日をまたいだ比べの線のずれ**：別の日の周を重ねるとき、測位の数 m のずれで線が平行にずれることがある（デジスパイスでは手で動かして直す）。航空写真の上なら気づきやすいので、まず見え方を確かめ、要るなら平行に動かす直しを足す
